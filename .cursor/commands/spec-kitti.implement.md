## Purpose

This command is the core of Spec-Kitti's autonomous implementation: it executes a complete Work Unit automatically, iterating through an Executor-Reviewer feedback loop until the code meets all quality standards, without human intervention.

## Prerequisites

Before running this command, ensure:

1. `work-units.json` generated by `/spec-kitti.tasks.shape`
2. `endpoint_mapping_schema.json` from `/spec-kitti.discovery`
3. `plan.md` with architectural guidelines
4. Active git branch for the feature

## Usage Modes

### Mode 1: Single Work Unit

```bash
/spec-kitti.implement WU-005
```

**Behavior**:
- Executes only WU-005
- Autonomous loop until APPROVED or MAX_ITERATIONS reached
- Generates code ready for developer review

### Mode 2: With Custom Iteration Limit

```bash
/spec-kitti.implement WU-005 --max-iterations 10
```

**Behavior**:
- Allows up to 10 correction attempts (default: 5)
- Useful for complex Work Units

## Orchestration Logic

### Autonomous Correction Loop

```python
def implement_work_unit(work_unit_id, max_iterations=5):
    """
    Execute Work Unit with autonomous correction loop.
    """
    # 1. Load Work Unit
    wu = load_work_unit(work_unit_id)
    
    # 2. Correction Loop
    iteration = 1
    status = "PENDING"
    feedback = None
    
    while iteration <= max_iterations:
        log(f"Iteration {iteration}/{max_iterations}")
        
        # STEP 1: EXECUTOR AGENT - Generate Code
        if iteration == 1:
            # Initial generation
            executor_input = {
                "work_unit": wu,
                "parity_contract": load_parity_contract(),
                "plan": load_plan()
            }
        else:
            # Correction mode with feedback
            executor_input = {
                "work_unit": wu,
                "parity_contract": load_parity_contract(),
                "plan": load_plan(),
                "feedback": feedback  # Review report from previous iteration
            }
        
        code_file = executor_agent.generate(executor_input)
        
        # STEP 2: REVIEWER AGENT - Validate Code
        review_result = reviewer_agent.review({
            "code_file": code_file,
            "work_unit": wu,
            "parity_contract": load_parity_contract()
        })
        
        # STEP 3: DECISION
        status = review_result.status  # APPROVED | NEEDS_REVISION | REJECTED
        
        if status == "APPROVED":
            log(f"Code approved after {iteration} iteration(s)")
            break
        
        # Prepare feedback for next iteration
        feedback = review_result.report
        iteration += 1
    
    # 4. FINAL RESULT
    if status == "APPROVED":
        log(f"Code approved and ready for review")
        log(f"Developer can now commit: {code_file}")
        # Mark task complete in tasks.md
        mark_task_complete(work_unit_id)  # finds WU-ID line, sets [x]
        return SUCCESS
    else:
        log(f"Failed after {max_iterations} iterations")
        log(f"Last review: {feedback}")
        return FAILURE
```

## Multi-Agent System Architecture

### Agent 1: Executor Agent

**Role**: Code generation from Work Unit specifications

**Skill**: `.cursor/skills/spec-kitti-implement/references/executor.md`

**Inputs** (defined in skill):
- Constitution + Discovery artifacts (architectural context)
- Work Unit JSON (subtasks, business rules, parity anchors)
- Architectural Plan (tech stack, patterns)
- Review Feedback (for corrections, iteration > 1)

**Outputs**:
- Production-ready code file at Work Unit `file_path`

### Agent 2: Reviewer Agent

**Role**: Code quality validation and feedback generation

**Skill**: `.cursor/skills/spec-kitti-implement/references/reviewer.md`

**Review Levels** (defined in skill):
1. **Requirements Compliance** (CRITICAL · 40%)
2. **Architecture Compliance** (ERROR · 25%)
3. **Constitution Compliance** (ERROR · 20%)
4. **Code Quality** (ERROR · 10%)
5. **Maintainability** (WARNING · 5%)

**Outputs**:
- Review report at `.spec-kitti/implementation/[WU-ID]-review-N.md`
- Status: APPROVED | NEEDS_REVISION | REJECTED

## Success vs Failure Criteria

### Success (Code Ready)

- All subtasks from Work Unit implemented
- All business rules (BR###) enforced
- All parity anchors (EP###) addressed
- Code quality score >= 90%
- Security checks passed
- Framework compliance met

### Failure (Manual Intervention)

- MAX_ITERATIONS reached without approval
- Critical security violations (passwords in logs, hardcoded secrets)
- Missing business rule enforcement
- Type safety violations
- Framework non-compliance

### Needs Revision (Auto-Correction)

- Minor code quality issues
- Missing error logging
- Long functions (> 50 lines)
- Performance warnings (N+1 queries)
- Maintainability issues

## Security Validations

Before approving code, the Reviewer Agent validates:

1. **No secrets**: No API keys, passwords, tokens in code
2. **No sensitive data in logs**: No passwords logged
3. **Framework compliance**: Uses framework security patterns
4. **Input validation**: All entry points validated
5. **Output sanitization**: Sensitive data removed from responses

### View Detailed Logs

Check the execution log:

```bash

```

### View Review Reports

Check why code was rejected:

```bash
cat .spec-kitti/implementation/WU-005-review-1.md
```

### Manual Correction

If max iterations reached:

1. Review last feedback: `.spec-kitti/implementation/WU-005-review-N.md`
2. Manually fix critical issues
3. Re-run: `/spec-kitti.implement WU-005`
